# Q2 v5 case and truth audit

E0 review note for the `q2-real-task` draft suite and its twelve cases, recorded as required
by [strategy §4 E0](../../documentation/mcp-evaluation-strategy.md#e0-case-and-truth-validation)
and [G-E0b](../../documentation/mcp-evaluation-strategy.md#818-gate-to-check-map).

- Suite: `q2-real-task` version 5, status `draft`, pinned revision `9643b5384da67f8d4c3b8a1e579d649eee691390`.
- Truth authority: TypeScript language service 6.0.3, using the subject's `tsconfig.json` and
  `tsconfig.test.json`.
- Scope: every case declares `scope: ["src/**"]`. Scope is grading metadata and is not sent
  to the agent, so each prompt must state its scope explicitly.

## Method

1. Materialize the pinned revision with `git archive` instead of evaluating the moving
   checkout.
2. Parse both TypeScript project files and create one program containing `src/` and `test/`.
3. Locate each declaration in source code and call the language service's
   `findReferences` at that declaration.
4. Compare the observed reference file set with `expectedFiles`, restricted to the case
   scope for impact cases, and confirm that every expected, context, and forbidden path
   exists at the pinned revision.
5. Run the case schema, suite loader, grader, and harness tests with
   `pnpm eval:list` and `pnpm eval:verify`.

`pnpm eval:check` additionally requires the subject checkout to be at the pinned revision.
It fails against a later checkout by design. Current `HEAD` differs from `9643b53`, but
`git diff 9643b53 HEAD -- src` is empty, so the audited ground truth is unchanged.

## Corpus gaps

These findings do not invalidate the twelve expected file sets. They block freezing the
suite and are carried into the case-building items.

- All four `implementation` cases are file-identification prompts. They have no exact
  allowed changed-file set and no deterministic post-run `check`, so they do not meet the
  implementation-case requirement in strategy §6. They must be replaced or accompanied by
  bounded change cases with checks before the suite is frozen.
- There are no `semantic` cases yet. The next suite must add at least six mechanically
  admitted semantic cases.
- `contextFiles` and `forbiddenFiles` are empty for every case. False-positive behavior and
  supporting-evidence allowance are therefore unexercised.
- Impact prompts now state their scope; future cases must keep prompt scope, `scope`, and
  `expectedFiles` consistent because the harness does not derive the prompt from `scope`.

## Verdict

E0b passes for all twelve cases: every expected file exists at `9643b53`, and every impact
set equals the language-service reference set inside the declared scope. The case schema,
suite loader, grader fixtures, and harness tests pass. The suite remains a draft until the
implementation and semantic gaps are resolved.
